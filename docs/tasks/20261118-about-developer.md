# Информация о разработчике

В приложении нигде не сказано, кто его сделал и куда писать об ошибках и предложениях. Нужен блок с информацией о разработчике: ник и email.

## Поведение

1. **Где.** На экране «Настройки» последней группой, после «Оформления», новая карточка «О приложении» с заголовком прописными, как у остальных групп (`SectionTitle`).
2. **Что в ней:**
   - «Версия» — `versionName` сборки (для отчётов об ошибках);
   - «Разработчик» — ник `ssortia`;
   - «Email» — адрес для обратной связи (уточнить у пользователя при реализации, в репозиторий до этого не записывать).
   Строки как у остальных пунктов настроек: подпись слева, значение справа, разделены линиями.
3. **Нажатие на email** открывает почтовое приложение с адресом в поле «Кому» и темой «RunTimer <версия>» (`Intent.ACTION_SENDTO` с `mailto:`). Если почтового приложения нет, адрес копируется в буфер обмена и показывается `Toast` «Адрес скопирован» (на Android 13+ система сама показывает уведомление о копировании, свой `Toast` там не нужен). Долгое нажатие тоже копирует адрес.
4. **Доступность.** TalkBack читает строку email одной кнопкой: «Email <адрес>, написать письмо»; версию и ник — обычным текстом.

## Как сделать

- Ник и адрес — строковые ресурсы без перевода (`translatable="false"`) в `strings.xml`, а не литералы в Compose. Версию брать из `BuildConfig.VERSION_NAME` (проверить, что `buildFeatures.buildConfig` включён) или из `PackageManager` в `MainActivity` и передавать в `AppSettingsContent` параметром: экран не должен сам лезть в Android API сверх `LocalContext` для интента.
- Интент письма собирать в `MainActivity` (колбэк `onWriteEmail`), а не в экране; `resolveActivity` на API 30+ без `<queries>` вернёт `null`, поэтому вызывать `startActivity` в `try`/`catch (ActivityNotFoundException)` и копировать адрес при ошибке, либо объявить `<queries>` для `mailto`.
- Тема письма собирается чистой функцией с версией параметром, тест на неё.
- Обратить внимание: email попадёт в публичный репозиторий и в APK; если это нежелательно, заменить на отдельный адрес для обратной связи до реализации.
- **Документация:** `USER_STORIES.md` (новая история), `docs/how-it-works.md` (экран настроек), `README.md` (контакт разработчика).
