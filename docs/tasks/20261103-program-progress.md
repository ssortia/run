# Экран прогресса по программе

Начинающий бегун идёт по программе из 11 недель (US-13) два-три месяца и сам решает, когда переходить на следующую неделю: не по календарю, а когда чувствует, что готов бежать дольше. Сейчас для этого решения у него нет опоры. Форма показывает только последнюю введённую тренировку. В истории есть даты и минуты, но понять по ним, сколько раз пробежана неделя, можно только сверкой параметров с таблицей программы. За долгую программу легко потерять ощущение, что движешься вперёд.

Нужен отдельный экран «Прогресс», который отвечает на вопрос «что я уже сделал по программе»: сколько раз пробежана каждая неделя, какие недели пройдены и когда была последняя пробежка. Экран только показывает факты. Он не советует, когда переходить дальше, и ничего не меняет на форме и в истории. Решение остаётся за человеком: «пройдена» значит лишь, что неделя пробежана 4 раза, перейти дальше можно и раньше.

Макет: https://claude.ai/artifact/WKnsAn8dCvkNbCqtUVcdik, артборд «Прогресс».

## Экран

```
┌──────────────────────────────────┐
│ ←  Прогресс                      │
│ ┌──────────────────────────────┐ │
│ │ 2  из 11 недель пройдено     │ │
│ │ ▬ ▬ ▭ ▭ ▭ ▭ ▭ ▭ ▭ ▭ ▭        │ │  деление на каждую неделю
│ └──────────────────────────────┘ │
│ ┌──────────────────────────────┐ │
│ │ ✓ Неделя 1           5 раз   │ │  4 и больше: галочка
│ │   Бег 1:00 · Ходьба 2:00 ×7  │ │
│ │                      20 окт  │ │
│ │ ✓ Неделя 2           4 раза  │ │
│ │ ◕ Неделя 3           3 раза  │ │  кольцо из 4 частей, закрашены 3
│ │ ○ Неделя 4               —   │ │
│ │ …                            │ │
│ └──────────────────────────────┘ │
└──────────────────────────────────┘
```

- **Итог.** Число пройденных недель «N из 11 недель пройдено» и полоса из 11 делений. Закрашены деления пройденных недель, а не первые N: недели можно проходить не по порядку. Начатые, но не пройденные недели на полосе не отмечаются.
- **Список всех 11 недель** в одной карточке с разделителями. Слева кольцо из 4 равных частей, по одной на завершённую пробежку: первая закрашена после одной пробежки, первая и вторая после двух, три после трёх, начиная сверху по часовой стрелке. После четырёх и больше вместо кольца стоит закрашенный круг с галочкой. Незакрашенные части видны тоном, а не пропадают. Для TalkBack у значка подпись «Пробежек 2 из 4» или «Неделя пройдена». Посередине «Неделя N» и параметры недели, как в шторке программы. Справа число завершённых пробежек («1 раз», «3 раза», «5 раз»), в том числе больше четырёх, и под ним дата последней. У недели без пробежек справа «—».
- **Без пробежек по программе** экран тот же: «0 из 11», все недели с прочерками. Отдельного пустого состояния нет.
- Пока поток записей не пришёл (`null`), показывается пустой экран с шапкой, без «0 из 11», чтобы не мигали прочерки.
- Строки списка не нажимаются: экран только для просмотра.

## Правила

- **Неделя пробежки** определяется по `runSec`, `walkSec` и `rounds` записи: у всех недель `WORKOUT_PRESETS` эти тройки разные. Пробежка с теми же параметрами, набранными вручную, засчитывается неделе: тренировка та же. Пробежки с параметрами не из программы не учитываются.
- **Засчитываются только завершённые пробежки** (`completed`). Остановленные видны в истории, но в прогресс не входят.
- **Неделя пройдена** после 4 завершённых пробежек (константа `RUNS_TO_PASS_WEEK = 4`). Пробежки сверх четырёх считаются и показываются, но значок от них не меняется. Порог ничего не блокирует: любую неделю можно выбрать на форме в любой момент.
- **Отдельного хранения нет.** Прогресс каждый раз считается из истории. Удаление записи в истории сразу меняет прогресс, удаление записи пройденной недели с ровно четырьмя пробежками возвращает кольцо из трёх частей. Начать программу заново значит очистить историю, отдельного сброса нет.

## Как сделать

1. **Логика.** Чистая функция без Android API в новом файле `ProgramProgress.kt`:

   ```kotlin
   const val RUNS_TO_PASS_WEEK = 4

   data class WeekProgress(val week: Int, val completedRuns: Int, val lastCompletedAtMs: Long?) {
       val passed: Boolean get() = completedRuns >= RUNS_TO_PASS_WEEK
       /** Сколько частей кольца закрашено, от 0 до 4. */
       val filledQuarters: Int get() = completedRuns.coerceAtMost(RUNS_TO_PASS_WEEK)
   }

   /** Все недели программы по порядку, в том числе без пробежек. */
   fun programProgress(runs: List<RunRecord>): List<WeekProgress>
   ```

   Неделю записи находит функция рядом с `presetWeekOf` в `WorkoutPreset.kt`, сравнение идёт через `WorkoutSettings.toWorkout()`, чтобы 1 мин 30 сек совпадали с 90 секундами записи. Подписи («Неделя», «раз»/«раза», формат даты) собираются отдельной функцией с подписями в параметрах, как `runRowText`. Склонение «раз» тоже чистая функция под тесты. Дата форматируется явным шаблоном по той же причине, что и в `runRowText` (CLDR в JDK и ICU на телефоне).
2. **Маршрут.** Новый маршрут `progress` в `NavHost` ветки `Idle` в `WorkoutScreen`, объявляется через `screen()`, как остальные. Переход через `navigate` в обёртке `dropUnlessResumed`, возврат через `popBackStack`. Данные из того же потока `runs`, что получает `history`: `collectAsStateWithLifecycle(initialValue = null)` внутри маршрута. Экран `ProgressContent` получает готовый список `WeekProgress` и про Room не знает.
3. **Вход.** Иконка «Прогресс» в верхней панели формы рядом с «Программой», «Историей» и «Настройками». Какую иконку взять и не перегружена ли панель, решить вместе с макетом редизайна. `contentDescription` «Прогресс» в `strings.xml`.
4. **Оформление.** По макету и общему стилю редизайна: тона карточек, `tnum` для чисел. Кольцо рисуется в `Canvas` четырьмя дугами по 90° с небольшими зазорами, толщина линии около 2 dp при значке 24 dp. Незакрашенные части и деления полосы тоном `#DCDCD8` в светлой и `#3A3B40` в тёмной теме: тон поля на карточке почти не виден. Цвет закрашенных частей, галочки и деления берётся из точки бега (`#047857` в светлой, `#10B981` в тёмной теме), а не из `primary`: на тёмном фоне `#047857` плохо виден.

Делать после редизайна (`docs/plans/20261103-redesign.md`): он задаёт верхнюю панель, иконки, тона карточек и меняет выбор недели.

Схема базы, `RunRecord`, сервис, форма и история не меняются.
