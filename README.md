# RunTimer

Простой интервальный таймер для бега под Android. Чередует отрезки бега и ходьбы, подаёт звуковой сигнал при каждой смене отрезка и другой сигнал в конце тренировки.

Пример: 2 минуты бега, 2 минуты ходьбы, 7 повторов. Это 14 отрезков и 28 минут тренировки.

Сценарии использования описаны в [USER_STORIES.md](USER_STORIES.md).

## Статус

Первая версия написана целиком: настройка тренировки, сигналы, фоновая работа, экран хода тренировки, уведомление. Приложение собирается, unit-тесты проходят.

На телефоне приложение ещё не запускалось, ручная проверка впереди. Поэтому всё, что зависит от устройства, пока не подтверждено: слышимость сигналов, работа при заблокированном экране, поведение на прошивках с экономией батареи. Сценарий проверки описан в плане первой версии в `docs/plans/`.

## Как это работает

Приложение нативное, на Kotlin. PWA здесь не подходит: при выключенном экране Android усыпляет JS-таймеры в браузере, и сигналы начинают опаздывать или пропадать.

- **Фоновая работа.** Таймер выполняется в foreground service `WorkoutService` типа `specialUse`, поэтому на время тренировки в шторке висит уведомление. Канал уведомлений с низкой важностью, обновления не издают звука. Нажатие на уведомление открывает приложение, кнопки «Стоп» в нём нет.
- **Сон процессора.** Partial wake lock не даёт процессору уснуть. Он берётся на длительность тренировки плюс одну минуту, поэтому при ошибке в логике снимется сам и не разрядит батарею.
- **Точность.** Сервис раз в 250 мс вычисляет текущий отрезок по времени от старта (`SystemClock.elapsedRealtime`), а не по счётчику тиков, поэтому ошибка не накапливается.
- **Звук.** Сигналы генерируются в коде и проигрываются через `AudioTrack`, аудиофайлы не нужны. Смена отрезка звучит как два коротких тона 880 Гц, финал как три восходящих тона 660, 880 и 1100 Гц. Они идут через канал будильника (`USAGE_ALARM`), поэтому их громкость регулируется громкостью будильника, а не медиа.
- **Финал.** После финального сигнала сервис ждёт его длительность и ещё 300 мс на задержку вывода звука, иначе конец сигнала мог бы обрезаться. Затем он останавливается, и уведомление исчезает. «Стоп» прекращает звук сразу, в том числе во время финального сигнала.
- **Настройки.** Хранятся в `SharedPreferences` и сохраняются при запуске тренировки. При первом запуске в полях стоит 2 мин / 2 мин / 7 повторов.
- **Интерфейс.** Экраны написаны на Jetpack Compose: это декларативный UI, похожий на React. Сервис публикует состояние тренировки через `StateFlow`, а экран только отображает его, поэтому экран можно закрыть и открыть заново. Цвет фона зависит от отрезка, есть светлая и тёмная темы.

## Расширение

Приложение может вырасти: замер расстояния, маршрут, история пробежек. Заранее сделано только то, что потом дорого менять:

- **Сервис отвечает за тренировку целиком, а не только за таймер.** Поэтому он называется `WorkoutService`, и запись GPS добавится рядом с таймером.
- **Логика отделена от Android.** `Workout.kt`, настройки, выбор сигнала и синтез тонов не зависят от системы и проверяются обычными unit-тестами. Расчёт дистанции стоит делать так же.
- **Экран зависит только от состояния.** Новые показатели становятся новыми полями в состоянии и элементами экрана, новые экраны добавляются как Compose-функции.

Что понадобится для GPS и истории, в первой версии этого нет:

- Разрешения `ACCESS_FINE_LOCATION` и `FOREGROUND_SERVICE_LOCATION`, а для `WorkoutService` тип foreground service `location`. Для Google Play это также упростит обоснование фоновой работы.
- Локальная база данных Room для хранения пробежек и точек маршрута.
- Библиотека карт для показа маршрута. Если карта будет от Google, понадобится API-ключ, поэтому библиотеку выбираем отдельно.

## Структура проекта

Код лежит в `app/src/main/java/com/ssortia/runtimer/`, тесты в `app/src/test/java/com/ssortia/runtimer/`, ресурсы в `app/src/main/res/`.

| Файл | Назначение | Аналогия из веба |
|---|---|---|
| `build.gradle.kts`, `app/build.gradle.kts`, `settings.gradle.kts` | Описание сборки | `package.json` + конфиг сборщика |
| `app/src/main/AndroidManifest.xml` | Экраны, сервисы и разрешения | `manifest.json` у PWA |
| `Workout.kt` | Чистая логика: какой идёт отрезок, сколько осталось, общий прогресс | Чистая функция без привязки к UI |
| `WorkoutSettings.kt` | Настройки в виде, как их вводит пользователь, и их проверка | Схема валидации формы |
| `WorkoutState.kt` | Состояние тренировки, выбор сигнала, форматирование времени | Типы состояния и селекторы |
| `SettingsStore.kt` | Чтение и запись настроек | `localStorage` |
| `MainActivity.kt` | Точка входа в интерфейс, запрос разрешения, старт и стоп сервиса | `index.html` + монтирование корневого компонента |
| `ui/WorkoutScreen.kt` | Выбор экрана по состоянию тренировки | Роутинг по состоянию |
| `ui/SettingsContent.kt` | Форма настроек и разбор ввода | React-компонент формы |
| `ui/ActiveContent.kt` | Экран идущей тренировки | React-компонент |
| `ui/Theme.kt` | Светлая и тёмная темы, цвета отрезков | Тема и CSS-переменные |
| `WorkoutService.kt` | Тренировка, работающая в фоне | Похоже на Service Worker, но работает постоянно |
| `NotificationText.kt` | Текст уведомления | Чистая функция форматирования |
| `Tones.kt` | Состав сигналов и синтез звука | Генерация буфера для Web Audio |
| `Beeper.kt` | Проигрывание сигналов | Web Audio API |

## Требования

- Для сборки: JDK 17 и Android SDK (`platforms;android-35`, `build-tools;34.0.0`). Android Studio не обязательна. Gradle 8.11.1 скачивается через Gradle Wrapper, для первой сборки нужен интернет.
- Для запуска: телефон с Android 8.0 (API 26) или новее.

Версии инструментов: Android Gradle Plugin 8.7.3, Kotlin 2.0.21, Compose BOM 2024.12.01, `compileSdk` и `targetSdk` 35.

## Сборка

Если `java` в системе не JDK 17, задайте `JAVA_HOME` на JDK 17, например `JAVA_HOME=<путь к JDK 17> ./gradlew test assembleDebug`.

Путь к Android SDK задаётся в `local.properties` (файл не хранится в репозитории):

```properties
sdk.dir=/home/ssortia/Android/Sdk
```

Сборка и тесты:

```bash
./gradlew test assembleDebug
```

Проверка lint:

```bash
./gradlew lintDebug
```

Готовый APK появится в `app/build/outputs/apk/debug/app-debug.apk`.

## Установка на телефон

1. Скопируйте `app-debug.apk` на телефон.
2. Откройте файл и разрешите установку из неизвестного источника.
3. На Android 13 и новее при первом нажатии «Старт» приложение запросит разрешение на уведомления, в них показывается ход тренировки. Без разрешения таймер работает, но уведомления не видно.

Подпись релизной версии не настроена, поэтому устанавливается отладочная сборка. Если телефон подключён по USB с включённой отладкой, можно установить командой `adb install app/build/outputs/apk/debug/app-debug.apk`.

## Известные ограничения

- На прошивках Xiaomi, Huawei, Samsung и других система может завершать фоновые приложения. Если таймер останавливается при выключенном экране, отключите для него экономию батареи.
- Если система завершит процесс приложения, тренировка теряется: сервис не перезапускается, и продолжить её нельзя. Настройки при этом сохраняются.
- Если громкость будильника на нуле, сигналов не будет слышно.
- Сигналы не приглушают музыку, поведение в наушниках на телефоне ещё не проверено.
- Foreground service типа `specialUse` подходит для личного использования, но при публикации в Google Play его нужно обосновывать при проверке. С появлением GPS тип сменится на `location`.
